# Zeeshan QA: V1 → V2 backend parity

Evidence is from the read-only `ZavSync-Backend-V1` checkout and the current V2 checkout. The QA source is `Zavsync from WhatsApp Business.xlsx`, Sheet1 rows 2–24. File paths below are repository-relative to their named version. V1 behavior is evidence of a business requirement, not automatic authorization to copy its implementation.

## Cross-cutting V1 evidence and exclusions

V1's direct company association, fixed numeric roles, broad model serialization, public announcement files, requester-supplied employee ID, plaintext company FBR token, request/payload/response logging, floating-point invoice/payroll calculations, and shared Invoice/FBR table cannot be reused unchanged. V2's company membership, UUID identity, private files, encrypted provider configuration, integer-minor-unit accounting, idempotency, audit, and distinct Accounting/FBR domains remain authoritative. The inspected V1 paths show global FBR rate mappings and status/role assumptions, but no verified company-ID-specific exception that warrants encoding into V2. No production database or provider was accessed.
